# Preserved whole-opening policies as possible future reacting references

The three standalone files are preserved even if a candidate fails its own improvement gate. They react only through observed second-shop selection, current market-order optimization, partial planting and observed failed-hire recovery. They do not load any workspace file at runtime, read episode identities/seeds, or retain the old source opening/controller. The helper reference audit and exact SHA bindings are in preflight.json and pool.json.

Archived donor portfolios at observation72 illustrate why they offer a different production reference from the old common wheat opening. These are archive reads, not candidate outcomes:

All three donor snapshots own only NW land. The shared166 donor also has one empty pasture. See archived_opening_portfolios.json for episode/seat provenance. A new opponent or the reused execution helpers may change these portfolios and subsequent shops; they are not guaranteed candidate states.

Source helper imports and final entrypoints have been inspected, and completed fast pilot outcomes are recorded separately. Original-framework native and actual file-loader compatibility remain pending. Failed saved-target promotion is not proof that a policy is either strong or unusable as a varied benchmark opponent. Any later use as a reference should bind these exact files, verify native execution, and freeze its role before measured outcomes.
