# Wider complete-schedule development screen

The latest100 baseline loses34 team fixtures across26 observed first-two-shop
pairs. Three pairs containing top20 losses are already in ROUTE_SEARCH_PLAN.md.
This experiment applies the same complete-schedule hypothesis to the other23
pairs. These are development data; neither fitting more branches nor the
resulting saved win percentage establishes an online gain.

Before these outcomes: enumerate every distinct incumbent-library continuation
whose full first144 raw actions match the executed common opening and first-shop
schedule. Change only one observed pair and its descendants per candidate.
Do not use opponent identity, seed, episode lookup, private rival data, future
shops or reserved replay outcomes. Preserve all existing queue/plant repairs.

Screen every such continuation on every losing latest100 fixture belonging to
that pair in seat0. Select up to3 candidates per pair with at least one target
win, ordered by target wins, summed target margin, then ascending route ID.

Check those selected candidates on ALL latest100 fixtures sharing their pair,
in BOTH seats. Require clean completion, no lost baseline winning seat and a
positive paired win-point gain. Choose the passing candidate with most wins,
then greatest minimum target margin, summed margin, ascending route ID.

Combine passing disjoint pairs with independently passing top20 route changes.
Freeze the combined exact bytes before the full200-game latest100 check. Any
candidate failing these rules is retained only as a rejected experiment.
The fixed latest100 becomes training data. Evaluate the frozen candidate and
exact cb76 on both reserved sets (400games each version), report every loss
and gain. No tuning on those reserved outcomes. Then apply PLAN.md's original
reacting, native/file-loader and untouched-seed gates to a survivor. No upload.
